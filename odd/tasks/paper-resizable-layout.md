## Objective

Let each user drag the lines of the ficha (the vertical separators between blocks and the column boundaries inside each block) so the ficha fits their screen, zoom and resolution. The content adapts to the new widths.

## Problem and why

The ficha is a literal replica of the paper card with fixed proportions (`md:w-80` for the medidas column, fixed `rem` tracks inside grids). Depending on zoom and resolution some blocks end up cramped. The user was offered an automatic responsive layout first and explicitly chose user-adjustable lines instead (2026-10-13).

## Decisions

- **Which lines**: vertical only. The main separator of every `PaperBody`, plus the internal column boundaries of each block. Horizontal lines are not draggable: heights are driven by content.
- **Persistence**: `localStorage`, per browser. This matches the goal (each machine has its own zoom and resolution) and needs no backend change. Sizes are stored as proportions, not pixels, so they survive zoom changes.
- **Shared layout**: `FichaForm` and `FichaCard` read the same stored layout. Repeated rows of the same grid (for example the five rows of medidas, or O.D./O.I. graduation rows) share one set of tracks, so a column moves in all of them at once.
- **Reset**: a visible control restores the default layout.
- **Small screens**: below `md` the ficha stacks vertically as it does today; handles are not shown.
- **PDF**: unaffected. It is generated by the Apps Script backend and does not read the screen layout.

## Authorized scope

`src/features/fichas/ui/**` and a new small layout module next to it (or under `src/lib`) for the pure logic and the store. No domain, API, repository or Apps Script changes. No new runtime dependencies.

## Constraints

- Next.js 16 with breaking changes: read the relevant guide under `node_modules/next/dist/docs/` before writing code (see `AGENTS.md`).
- No hydration mismatch: the server render and the first client render use the default layout; the stored layout is applied after mount.
- Every track has a minimum size so inputs never collapse or overflow their block.
- Handles work with mouse and touch (pointer events) and with the keyboard (`role="separator"`, arrow keys), and are not printed.
- Default layout must look the same as today.

## Acceptance criteria

- Dragging the main separator of each body block resizes both sides and the content reflows.
- Dragging an internal column boundary resizes that column in every row of the same grid.
- Layout survives a reload and applies to both the form and the read-only card.
- The reset control restores the current default look.
- A corrupt or outdated stored value falls back to the default without errors.
- typecheck, lint, tests and build green.
