### Bloque 3 — Formateador de fechas (feedback del usuario)

El usuario reportó: "El usuario tiene que solamente ingresar los números y la fecha se tiene que setear sola en DD/MM/AAAA."

**T11 — DateInput**: lógica pura extraída a `dateInputLogic.ts` (`parseAny`, `isoToDisplay`) testeable sin DOM. Componente `DateInput.tsx` que solo acepta dígitos + `/`, auto-formatea progresivamente. `PaperDateField` envuelve el `DateInput` con el look paper. Aplicado a `fechaEntrada` y `recetaFecha`.

**Bugs encontrados durante testing**:
1. `parseAny("29092")` propagaba ISO incorrecto (`"2029-09-02"`) porque `safeIso("2", "09", "29")` matcheaba el regex DMY de `parseFecha`. Fix: no emitir ISO hasta tener exactamente 8 dígitos.
2. `isoToDisplay("not-a-date")` devolvía `"date/0a/not"` porque `split("-")` produce 3 strings truthy. Fix: validar con regex `\d{4}`, `\d{1,2}`, `\d{1,2}`.
3. POST con `"31/02/2026"` o `"29/09"` rompía con 400. Fix: `parseFechaLenient` que devuelve `""` en lugar de throw; el schema Zod lo usa para fechas.

3. **Auth con Google + allowlist** — login obligatorio antes de salir de local. Protege los endpoints de escritura (PDF §9.1).
4. **OCR/IA con revisión humana** — Fase 5 del PDF. Crear interface `FichaExtractor` y al menos una implementación mock o real.
5. **Tests de UI** — instalar `@testing-library/react` + `@testing-library/user-event` + `jsdom`, agregar tests para los componentes que tengan lógica no trivial.
6. **Atajos de teclado y navegación más rica** — fase de pulido UX. Cmd+K para búsqueda global, atajos de guardado/cancelar en edit mode.
7. **Reportes** — la card "Reportes" del sidebar está deshabilitada con badge "PRONTO". Implementar al menos un reporte básico (fichas creadas por mes, ingresos del día, etc.).
8. **Backup/exportación periódica** — PDF §12 menciona esto como precaución para cuando el sistema sea crítico. Exportar `.data/fichas.json` (o Sheets) a un destino configurable.

### Decisiones pendientes

- **Proveedor de OCR/IA**: OpenAI vs Gemini vs Claude. Decidir antes de implementar Fase 5.
- **Deploy target**: Vercel es el default. Si se necesita self-hosting, ajustamos variables de entorno y `next.config.ts`.
- **Allowlist de emails** para auth: ¿dónde se define la lista? ¿en una Sheet auxiliar, en una variable de entorno, en un archivo JSON?
- **Criterio de commits** antes de seguir: ¿una rama por feature, un commit por unidad, commits por el orquestador cuando el usuario lo pida?

### Riesgos / cosas a no romper

- El normalizador `parseFecha` mantiene la firma estricta porque hay tests que dependen de que tire error. Si alguien lo cambia a lenient por accidente, esos tests rompen — es una buena señal.
- El mutex de `NRO_FICHA` es en memoria. Si en algún momento se corre la app detrás de un balanceador con varias instancias, va a haber duplicados. El switch a Sheets con `LockService` resuelve eso.
- shadcn 4 con `@base-ui/react` cambia la API de componentes en cada minor. Si actualizamos shadcn, revisar `Button` (no `asChild`), `Select` (onValueChange puede ser `null`).
- Tailwind v4 no usa `tailwind.config.ts`; cualquier config de tema vive en `globals.css` vía `@theme`.
